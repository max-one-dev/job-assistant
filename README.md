# Job Assistant

Персональный помощник в поиске работы на hh.ru. Читает **публичные** страницы вакансий
(как обычный посетитель без логина), сверяет с резюме по системе баллов, а анализ и
сопроводительные письма делает Claude Code. Автооткликов нет — отклик отправляет человек.

> Официальный API hh для соискателей закрыт (с 15.12.2025), поэтому используется чтение
> публичных страниц. Запросы редкие и с паузами — только для личного использования.

## Структура

```
Job Assistant/
├── config.json          # настройки поиска и система баллов (правится руками)
├── README.md
├── src/
│   ├── collect.py        # поиск → парсинг → скоринг → merge в store.json
│   └── build_report.py   # store.json → report.html
├── data/
│   ├── store.json        # ЕДИНЫЙ ЖУРНАЛ: все вакансии + статус + история + письма
│   ├── report.html       # отчёт для просмотра в браузере
│   ├── SCHEMA.md         # справочник по данным (что хранится и откуда берётся)
│   └── logs/
└── resumes/
    ├── [profile1].pdf
    ├── [profile2].pdf
    ├── [profile1].txt     # текст резюме — эталон для профиля 1
    └── [profile2].txt     # текст резюме — эталон для профиля 2
```

## Как пользоваться

1. **Обновить вакансии** — попросить Claude Code «обнови вакансии» (запустит `collect.py`).
   Новые добавляются в `store.json`, старые **не удаляются**; у виденных обновляется `last_seen`.
2. **Письма** — Claude пишет сопроводительные для подходящих и складывает в `store.json`.
3. **Отчёт** — `python src/build_report.py` собирает `data/report.html`. Открыть в браузере,
   отфильтровать по вердикту/статусу, скопировать письмо, нажать «Откликнуться» (на hh — вручную).

Запуск скриптов (важно UTF-8, иначе кириллица в логах падает на cp1251):
```
PYTHONIOENCODING=utf-8 python src/collect.py
PYTHONIOENCODING=utf-8 python src/build_report.py
```

## Статусы вакансии (веду вместе с Claude как карьерным консультантом)

`new` · `interested` · `applied` · `interview` · `offer` · `rejected` · `skipped`

Сообщаешь Claude статус («откликнулся на 134443381», «отказ по 135273761») — он проставляет
статус и дописывает событие в `history` вакансии. Так копится история для советов.

## Система баллов

Задаётся в `config.json` (обязательные/желательные/знакомые технологии и минусы).
Профиль резюме под письмо выбирается автоматически по типу вакансии.

## Engineering decisions

**Почему store.json — append-only журнал, а не перезаписываемый список**

Вакансии никогда не удаляются из `store.json`. При каждом обновлении новые записи добавляются, у существующих обновляется только `last_seen`. Это осознанное решение: если вакансию снимают с публикации через день после отклика, вся история (письмо, статус, дата) остаётся. Данные фиксируются на момент сбора — это аналог иммутабельного лога событий, а не снимка текущего состояния hh.

**Как решается дедупликация**

Уникальный ключ — `id` вакансии с hh.ru. При парсинге новая вакансия добавляется только если id отсутствует в журнале; иначе обновляется только `last_seen`. В отчёте дополнительный уровень дедупликации: если одна и та же компания публикует дубли под разными id (такое бывает), `build_report.py` оставляет только лучший вариант по приоритету статуса → письма → вероятности.

**Почему без официального API hh**

Официальный API hh.ru для соискателей закрыт с декабря 2025. Проект читает те же публичные HTML-страницы, которые видит любой браузер, извлекая встроенный JSON-объект `HH-Lux-InitialState`. Это единственный доступный способ автоматизации на стороне соискателя. Запросы намеренно редкие (2 сек между страницами) — проект не является скрейпером в промышленном смысле.

**Как разделены профили резюме**

Два текстовых профиля резюме отражают реальные различия в позиционировании: специализированные роли требуют акцента на конкретной экосистеме, тогда как general backend-роли — на архитектуре и универсальном стеке. Логика выбора профиля закреплена в `.claude/PROMPT.md` и применяется Claude при написании каждого письма. Оба профиля описывают один и тот же опыт, но расставляют разные акценты.

**Как организована история статусов**

Каждое изменение статуса не перезаписывает предыдущее, а добавляет событие в массив `history` вакансии: `{event, ts}`. Это позволяет видеть полный путь вакансии — от «найдена» до «оффер» или «отказ» — и использовать историю для карьерных советов: какие типы вакансий регулярно приводят к интервью, на каком этапе обычно приходит отказ.
