# Job Assistant

Персональный помощник в поиске работы на hh.ru. Читает **публичные** страницы вакансий
(как обычный посетитель, без логина), сверяет с резюме по системе баллов, а анализ и
сопроводительные письма делает Claude Code. Автооткликов нет — отклик отправляет человек.

> Официальный API hh для соискателей закрыт (с 15.12.2025), поэтому используется чтение
> публичных страниц. Запросы редкие и с паузами — только для личного использования.

## Быстрый старт

### 1. Настройка

```bash
cp config.json.example config.json
cp .claude/CLAUDE.md.example .claude/CLAUDE.md
cp .claude/PROMPT.md.example .claude/PROMPT.md
cp .claude/CAREER_ASSISTANT_V2.md.example .claude/CAREER_ASSISTANT_V2.md
cp resumes/backend.txt.example resumes/backend.txt
```

Заполни значения в `[СКОБКАХ]` в каждом файле.

### 2. Запуск

**Двойной клик `start.bat`** — запускает локальный сервер и открывает отчёт в браузере.

Или вручную:
```bash
set PYTHONIOENCODING=utf-8
python src/serve.py
# → http://localhost:8765/
```

## Интерфейс отчёта

`data/report.html` открывается через сервер (`start.bat`) и даёт полный контроль над вакансиями.

### Панель инструментов (шапка)

| Элемент | Что делает |
|---------|-----------|
| **☀/🌙 Тема** | Переключение светлой/тёмной темы (сохраняется в localStorage) |
| **⊟/⊞ Компакт** | Компактный режим карточек — скрывает детали, оставляет название + кнопки |
| **↕ Сортировка** | Сортировка карточек: по рейтингу / по дате публикации / по дате добавления |

### Сайдбар — верхняя панель действий

Управление обновлением и экспортом перенесено в верх сайдбара. Каждая секция: лейбл → селект + кнопка.

**Секция «Обновление»** — выбор режима + кнопка ▶:

| Режим | Что делает |
|-------|-----------|
| Проверить закрытые | Проверяет видимые вакансии (new/interested/applied/interview/offer) на hh.ru — закрытые переводит в «Закрыта» |
| Обновить без проверки актуальности | Синхронный pipeline: `collect` → `rescore` → `build_report` → `export` |
| Обновить с проверкой актуальности в фоне | То же в фоне — браузер не зависает, прогресс показывается в строке состояния |

**Секция «Экспорт в vacancies.json»** — выбор пресета + кнопка 💾:

| Пресет | Фильтр |
|--------|--------|
| Необработанные | Новые вакансии с высоким рейтингом, без письма |
| Мои отклики | Статусы: interested / applied / interview / offer / rejected |
| Рекомендации | Статусы: new + interested (видимые) |
| Все из отчёта | Все не-архивные вакансии |
| Настроить | Открывает модальное окно кастомной конфигурации |

При выборе «Настроить» появляется кнопка **⚙ Настроить** — модальное окно с выбором полей, статусов, мин. зарплаты/рейтинга, вероятности, лимита строк и сортировки. Конфиг сохраняется в localStorage.

**Строка состояния** — прогресс операций отображается под секциями действий.

### Сайдбар (фильтры)

Фильтры раскрываются/сворачиваются, состояние сохраняется в localStorage. Синяя точка на заголовке раздела — активный фильтр внутри. Над карточками появляются теги активных фильтров с кнопкой `×` для сброса.

| Раздел | Варианты |
|--------|---------|
| **Статус** | все / новые / интересно / откликнулся / собес / оффер / отказ / пропущ. / Закрыта |
| **Ревью** | все / 👀 непросм. / ✓ просм. |
| **Шанс** | все / 🟢 90+ / 🟡 75–89 / 🟠 60–74 / 🔴 <60 |
| **Свежесть** | все / 🔥 ≤3 дн / ≤14 дн / ≤30 дн / 🕰 стар. / без даты |
| **Приоритет** | все / ⭐ WordPress |

Кнопка **✕ Сбросить (N)** в подвале сайдбара показывает количество активных фильтров.

### Сортировка

Dropdown в шапке: по рейтингу (умолчание) / по дате публикации ↓ / по дате добавления ↓. Выбор сохраняется в localStorage.

### Карточка вакансии

Каждая карточка показывает:
- **Процент совпадения** и **цвет рамки** по шансу (🟢🟡🟠🔴)
- Совпадения по ключевым словам, риски, темы для подготовки к интервью
- Флаги: свежесть, ⭐ WordPress, ✓ просмотрено, тип занятости
- Раскрываемые блоки: навыки + описание, история изменений
- Сопроводительное письмо (если написано) с кнопкой «Копировать»

**Кнопки действий:**

| Кнопка | Статус, при котором видна | Целевой статус |
|--------|--------------------------|---------------|
| ✓ Откликнулся | любой кроме applied и archived | applied |
| 🎯 Собес | только applied | interview |
| ✕ Отказ | только applied | rejected |
| ⊘ Пропустить | любой кроме skipped и archived | skipped |
| 👁 Просмотрено | если не просмотрено | — (пишет в feedback.json) |

При смене статуса на applied/interview/offer вакансия **автоматически** помечается просмотренной.

## Pipeline (что и когда запускается)

```
collect.py
  ↓ читает config.json, парсит hh.ru, добавляет новые вакансии в store.json

rescore.py
  ↓ пересчитывает баллы/вероятности/band по текущему config.json
  ↓ дедуплицирует new-вакансии с одинаковым (name, company) → дубли → skipped

build_report.py
  ↓ читает store.json + feedback.json, собирает data/report.html
  ↓ авто-помечает applied/interview/offer как просмотренные в feedback.json

export_vacancies.py [mode]
  ↓ сохраняет подмножество вакансий в data/vacancies.json

check_closed.py
  ↓ проходит по всем видимым вакансиям (new/interested/applied/interview/offer)
  ↓ 3 параллельных воркера, пауза 2 сек между запросами каждого воркера
  ↓ детектирует закрытие через HH-Lux-InitialState JSON: approved=false / closedForApplicants=true / HTTP 404
  ↓ если закрыта — статус → archived, запись в history; пересобирает отчёт
```

`build_report.py` вызывается автоматически после каждой смены статуса через сервер.

## Статусы вакансии

```
new → interested / applied / skipped / rejected
new → skipped  (авто: дубль другой вакансии этой же компании)
applied → interview / rejected / archived
interview → offer / rejected
any → archived  (авто: вакансия закрыта на hh.ru)
```

| Статус | Когда |
|--------|-------|
| `new` | Найдена, ещё не обработана |
| `interested` | Интересна, но письмо ещё не написано |
| `applied` | Отклик отправлен на hh.ru |
| `interview` | Пришло приглашение на собеседование |
| `offer` | Получен оффер |
| `rejected` | Отказ (с любой стороны) |
| `skipped` | Пропущена вручную или авто-дедупликацией (дубль) |
| `archived` | Вакансия закрыта на hh.ru (авто через «Обновить статусы») |

Статус меняется кнопкой в карточке. Каждое изменение записывается в `history` вакансии.

## Система баллов

Задаётся в `config.json`:
- `must_have` — обязательные технологии (высокий вес)
- `nice_to_have` — желательные
- `known` — знакомые/понимаемые
- `minus` — штрафные слова (senior, bitrix и т.д.)
- `probability.target_score` — порог для 100% вероятности

Вакансии с вероятностью < 50% скрыты из отчёта (кроме тех, что уже в воронке).

## Просмотренные вакансии (feedback.json)

`data/feedback.json` хранит пометки о просмотре и оценки Claude. Вакансия считается просмотренной если:
- Нажата кнопка **👁 Просмотрено** на карточке
- Статус изменён на applied / interview / offer (авто)
- Claude записал анализ в ходе сессии проверки

## Engineering decisions

**Почему store.json — append-only журнал, а не перезаписываемый список**

Вакансии никогда не удаляются из `store.json`. При каждом обновлении новые записи добавляются,
у существующих обновляется только `last_seen`. Это осознанное решение: если вакансию снимают
с публикации через день после отклика, вся история (письмо, статус, дата) остаётся.
Данные фиксируются на момент сбора — аналог иммутабельного лога событий.

**Как решается дедупликация**

Уникальный ключ — `id` вакансии с hh.ru. При парсинге новая вакансия добавляется только если
id отсутствует в журнале. Второй уровень: `rescore.py` при каждом пересчёте ищет `new`-вакансии
с одинаковым `(name, company)` и переводит дубли в `skipped` (приоритет: воронка > письмо >
вероятность). Это делает счётчик «Обновить статусы» точно равным числу карточек в отчёте.

**Почему без официального API hh**

Официальный API hh.ru для соискателей закрыт с декабря 2025. Проект читает те же публичные
HTML-страницы, которые видит любой браузер, извлекая встроенный JSON-объект
`HH-Lux-InitialState`. Это единственный доступный способ автоматизации на стороне соискателя.
Запросы намеренно редкие (2 сек между страницами) — проект не является скрейпером
в промышленном смысле.

**Как разделены профили резюме**

Несколько текстовых профилей резюме отражают реальные различия в позиционировании:
специализированные роли требуют акцента на конкретной экосистеме, тогда как general
backend-роли — на архитектуре и универсальном стеке. Логика выбора профиля закреплена
в `.claude/PROMPT.md` и применяется Claude при написании каждого письма.

**Как организована история статусов**

Каждое изменение статуса не перезаписывает предыдущее, а добавляет событие в массив
`history` вакансии: `{date, event}`. Это позволяет видеть полный путь вакансии —
от «найдена» до «оффер» или «отказ» — и использовать историю для карьерных советов.
