## 1. Что это и как работает

Job Assistant — локальный инструмент для поиска работы на hh.ru. Он автоматизирует рутину: вместо ручного просмотра десятков вакансий ты видишь только те, что реально подходят под твой профиль.

**Что делает:**
- Читает публичные страницы hh.ru (без логина и API-ключей)
- Оценивает каждую вакансию по твоим правилам и присваивает баллы
- Показывает цветной интерактивный отчёт в браузере
- Хранит историю всех вакансий, статусы и готовые письма
- Помогает Claude Code писать честные сопроводительные письма

**Что не делает:**
- Не откликается автоматически — это всегда делаешь ты вручную
- Не использует официальный API hh (он закрыт для соискателей с декабря 2025)
- Не хранит данные в облаке — всё локально на твоей машине

**Принцип работы:**

```
hh.ru (публичные страницы)
         ↓
    collect.py           ← парсинг + скоринг
         ↓
    store.json           ← единый журнал (никогда не удаляется)
         ↓
   build_report.py       ← генерация HTML
         ↓
    report.html          ← смотришь в браузере через serve.py
```

## 2. Требования и установка

### Что нужно

- **Python 3.8 или новее** — стандартная библиотека, дополнительных пакетов не нужно
- **Claude Code** — для анализа вакансий и написания писем
- **Windows** (есть `start.bat`) или **macOS/Linux** (запуск через терминал)

### Проверка Python

```bash
python --version
# или
python3 --version
```

Если Python не установлен, скачай с [python.org](https://python.org) и при установке поставь галку **"Add Python to PATH"**.

### Клонирование или копирование проекта

Просто скопируй папку проекта на свой компьютер. Никаких `npm install`, `composer install` или `pip install` не нужно.

### Структура файлов

```
Job Assistant/
├── config.json              # твои настройки поиска и скоринга
├── start.bat                # быстрый запуск (Windows)
├── README.md
├── src/
│   ├── collect.py           # сбор вакансий с hh.ru
│   ├── rescore.py           # пересчёт баллов без парсинга
│   ├── build_report.py      # генерация report.html
│   ├── export_vacancies.py  # экспорт в vacancies.json
│   └── serve.py             # локальный веб-сервер
├── data/
│   ├── store.json           # главный журнал (создаётся при первом запуске)
│   ├── report.html          # отчёт в браузере (пересобирается)
│   ├── vacancies.json       # экспорт (пересобирается)
│   ├── SCHEMA.md            # справочник по полям store.json
│   └── logs/
├── resumes/
│   ├── [profile1].txt       # текст резюме — основной профиль
│   ├── [profile2].txt       # текст резюме — специализированный профиль
│   └── *.pdf                # PDF-версии (справочно, скриптами не читаются)
└── .claude/
    ├── CLAUDE.md            # главный конфиг Claude Code
    ├── PROMPT.md            # профиль кандидата и правила написания писем
    └── CAREER_ASSISTANT_V2.md  # правила оценки вакансий
```

## 3. Запуск сервера

### Windows — самый простой способ

Двойной клик на `start.bat`. Откроется консоль и браузер с отчётом.

### Через терминал (любая ОС)

```bash
cd "путь/до/Job Assistant"
python src/serve.py
```

Сервер запустится на `http://localhost:8765/` и сам откроет браузер.

### Что происходит при первом запуске

Если `data/store.json` не существует или пустой — отчёт будет пустым. Сначала нужно [собрать вакансии](#71-каждый-день-утром).

### Остановка сервера

В терминале: `Ctrl+C`. В окне `start.bat` — закрыть окно.

## 4. Настройка под себя

Это самый важный раздел, если ты адаптируешь проект под свой профиль.

### 4.1 Поисковые запросы — `config.json`

Открой `config.json` и найди секцию `search`:

```json
"search": {
    "queries": ["[TECH_1]", "[TECH_2]", "[TECH_3]"],
    "schedule": "remote",
    "area": "",
    "items_on_page": 50,
    "max_pages": 2,
    "request_delay_sec": 2.0,
    "max_new_details_per_run": 40
}
```

**Что менять:**

| Поле | Что делает | Пример |
|------|-----------|--------|
| `queries` | Ключевые слова для поиска на hh | `["Python", "Django", "FastAPI"]` |
| `schedule` | Формат работы: `remote`, `fullDay`, `shift`, `flexible`, `flyInFlyOut` | `"remote"` |
| `area` | Код города hh.ru (пусто = вся Россия) | `"1"` — Москва, `"2"` — СПб |
| `max_pages` | Страниц на каждый запрос (50 вакансий/стр) | `2` = 100 вакансий на запрос |
| `max_new_details_per_run` | Сколько новых вакансий загружать детально за раз | `40` |
| `request_delay_sec` | Пауза между запросами в секундах | `2.0` — не уменьшай |

**Совет:** Начни с 2–3 ключевых запроса. Слишком широкий поиск даст много мусора.

### 4.2 Зарплатные пороги — `config.json`

В секции `v2.salary`:

```json
"salary": {
    "min": 0,
    "comfortable": 0,
    "target": 0
}
```

Замени значения на свои. Если зарплата в вакансии не указана — штрафов нет.

### 4.3 Ключевые слова скоринга — `config.json`

Секция `v2.add` — технологии, которые прибавляют баллы:

```json
"add": {
    "[TECH_PRIMARY]": 35,
    "[TECH_SECONDARY]": 20,
    "Backend": 20,
    "REST API": 15,
    ...
}
```

Секция `v2.penalty` — технологии, которые снижают вероятность:

```json
"penalty": {
    "[FRAMEWORK]_2y": -25,
    "react_primary": -20,
    ...
}
```

**Принцип:** Высокие бонусы — твои сильные стороны. Большие штрафы — то, чего у тебя нет и без чего не возьмут.

### 4.4 Профиль кандидата — `.claude/PROMPT.md`

Это главный файл для Claude. Он определяет:
- Кто ты как специалист
- Что можно упоминать в письмах
- Что нельзя упоминать
- Как выбирать профиль резюме

**Что адаптировать под себя:**

1. Раздел `# КАНДИДАТ` — замени на свой стек и опыт
2. Раздел `# КАК ВЫБИРАТЬ ПРОФИЛЬ` — опиши, когда использовать какое резюме
3. Раздел `# ЧТО МОЖНО УПОМИНАТЬ` / `# ЧТО НЕЛЬЗЯ ПИСАТЬ` — честно укажи свои границы
4. Раздел `# BITRIX` — замени на другую технологию, которую хочешь избегать

**Главное правило:** Не придумывай опыт. Письма должны отражать реальный уровень — иначе на собеседовании будет провал.

### 4.5 Правила оценки вакансий — `.claude/CAREER_ASSISTANT_V2.md`

Здесь описаны типы вакансий и вероятности получить интервью. При адаптации нужно пересмотреть:

- Типы вакансий — назови по своему стеку
- Вероятности по типам (`type_prob`) — оцени реалистично под свой уровень
- Список `reject_types` — что никогда не рассматривать

### 4.6 Резюме — `resumes/`

Добавь текстовые версии своих резюме:

- `resumes/[profile1].txt` — основной профиль
- `resumes/[profile2].txt` — специализированный профиль (или второй вариант)

Формат свободный — это текст, который Claude читает при написании письма. Можно скопировать текст из PDF или написать в произвольном формате.

**Важно:** Имена файлов могут быть любыми — главное прописать их в `.claude/PROMPT.md` в разделе выбора профиля.

### 4.7 Общие правила Claude — `.claude/CLAUDE.md`

Здесь прописан опыт кандидата для общего контекста (годы опыта, технологии, зарплатные ожидания). Поправь под себя.

## 5. Работа с отчётом

После запуска сервера открой `http://localhost:8765/` в браузере.

### 5.1 Цветовые полосы

Вакансии делятся на 4 группы по итоговой вероятности интервью:

| Цвет | Вероятность | Что делать |
|------|-------------|-----------|
| Зелёная | 90%+ | Откликнуться в первую очередь |
| Жёлтая | 75–89% | Хорошие шансы, стоит откликнуться |
| Оранжевая | 60–74% | Рассмотреть при наличии времени |
| Красная | <60% | Скорее всего не подойдёт |

### 5.2 Теги «Плюсы» и «Риски»

Под каждой вакансией показаны теги — что совпадает с твоим профилем (плюсы) и что может стать проблемой (риски). Это разбивка по правилам из `config.json`.

### 5.3 Фильтры

В верхней части отчёта есть фильтры:

- **По цвету** — показать только зелёные/жёлтые
- **По категории** — A (обязательно откликнуться), B (по возможности), C (пропустить)
- **По статусу** — новые, интересные, отклики, собеседования
- **По свежести** — 0–3 дня, 3–14 дней и т.д.
- **👀 Непросмотренные** — вакансии, которые ты ещё не просматривал

### 5.4 Кнопки действий

В каждой карточке вакансии есть кнопки:

| Кнопка | Действие |
|--------|---------|
| Открыть на hh | Переход на страницу вакансии |
| Откликнуться | Помечает статус как `applied` + открывает hh |
| Пропустить | Помечает статус как `skipped` (убирает из основного вида) |
| Отклонить | Помечает статус как `rejected` |

### 5.5 Кнопка «Обновить»

Кнопка в шапке отчёта запускает полный цикл обновления:
1. `collect.py` — сбор новых вакансий с hh.ru (~1–2 минуты)
2. `rescore.py` — пересчёт баллов по текущим правилам
3. `build_report.py` — пересборка отчёта
4. Страница перезагружается автоматически

## 6. Написание писем через Claude

Это основной способ взаимодействия с Claude Code для написания писем.

### 6.1 Как попросить написать письмо

Открой Claude Code в папке проекта и напиши что-то вроде:

```
Напиши сопроводительное письмо для вакансии 135784513
```

Claude автоматически:
1. Найдёт вакансию в `store.json`
2. Прочитает описание и требования
3. Выберет подходящий профиль резюме
4. Напишет честное письмо по правилам из PROMPT.md
5. Сохранит письмо в `store.json`

### 6.2 Как попросить написать письма для нескольких вакансий

```
Напиши письма для всех зелёных вакансий без писем
```

или

```
Напиши письма для вакансий 135784513, 135758568, 135776515
```

### 6.3 Запросить анализ вакансии перед письмом

```
Проанализируй вакансию 135784513 — стоит ли откликаться?
```

Claude вернёт:
- Тип вакансии
- Вероятность интервью
- Совпадения и риски
- Рекомендацию откликаться или нет

### 6.4 Структура письма

Claude пишет письма по правилам из `.claude/PROMPT.md`:

1. Короткое приветствие
2. Почему заинтересовала вакансия
3. Релевантный опыт (только реальный)
4. Честное упоминание пробелов (если есть)
5. Приглашение к общению

**Объём:** 100–180 слов. **Стиль:** разговорно-деловой.

### 6.5 Посмотреть готовое письмо

Письма хранятся в `store.json` и отображаются в отчёте в карточке каждой вакансии.

Чтобы скопировать письмо — раскрой карточку вакансии в отчёте.

### 6.6 Честность — главный принцип

Claude **никогда не придумывает** опыт. Если в вакансии требуется навык, которого у тебя нет — об этом будет написано честно:

> "Сейчас активно изучаю [фреймворк] и хочу развиваться именно в этом направлении."

Это не слабость — это то, что можно подтвердить на собеседовании.

## 7. Ежедневный workflow

### 7.1 Каждый день утром

1. **Обновить вакансии** — нажать кнопку «Обновить» в отчёте или через Claude:

   ```
   Обнови список вакансий и запусти сервер
   ```

2. **Просмотреть новые** — отфильтровать по «Непросмотренные» и зелёному/жёлтому цвету

3. **Написать письма** — для интересных вакансий попросить Claude написать письма

4. **Откликнуться** — нажать «Откликнуться» в отчёте, перейти на hh и отправить отклик вручную

### 7.2 После отклика

Сообщи Claude об изменении статуса:

```
Откликнулся на вакансию 135784513
```

Claude обновит статус с `new` на `applied` и запишет событие в историю.

### 7.3 После ответа работодателя

```
Пришло приглашение на интервью по вакансии 135784513
```

или

```
Отказ пришёл по вакансии 135758568 — не подошёл опыт
```

Это важно для накопления истории и карьерных советов.

## 8. Управление статусами вакансий

### Воронка вакансий

```
new → interested → applied → interview → offer
                ↘ skipped
                ↘ rejected
                ↘ archived
```

| Статус | Смысл |
|--------|------|
| `new` | Только появилась, не просматривалась |
| `interested` | Отмечена как интересная |
| `applied` | Отклик отправлен |
| `interview` | Пригласили на собеседование |
| `offer` | Получен оффер |
| `rejected` | Отказ (с их или твоей стороны) |
| `skipped` | Пропущена сознательно |
| `archived` | Архив (убрать из активного вида) |

### Как менять статус

**Через кнопки в отчёте** — для `applied`, `rejected`, `skipped`.

**Через Claude** — для остальных:

```
Обнови статус вакансии 135784513 на interview
```

```
Пришёл оффер по вакансии 135758568
```

## 9. Архитектура данных

### Главный файл: `data/store.json`

Единственный источник правды. Всё остальное (отчёт, экспорт) пересобирается из него.

**Что хранится по каждой вакансии:**

```json
{
  "id": "135784513",
  "name": "[Stack] Developer",
  "company": "Название компании",
  "salary": {"from": 150000, "to": 200000, "currency": "RUR"},
  "published_at": "2026-08-03",
  "url": "https://hh.ru/vacancy/135784513",
  
  "score": 98,
  "probability": 0.9016,
  "band": "green",
  "category": "A",
  "vac_type": "[type]",
  
  "matched": {
    "pluses": ["[TECH_1]", "Backend", "REST API", "Docker"],
    "risks": []
  },
  "review_topics": ["Docker", "REST API"],
  
  "status": "applied",
  "letter": "Добрый день!...",
  "profile": "[profile]",
  
  "first_seen": "2026-08-03T10:00:00+03:00",
  "last_seen": "2026-08-03T10:00:00+03:00",
  "history": [
    {"event": "found", "ts": "2026-08-03T10:00:00+03:00"},
    {"event": "letter_written", "ts": "2026-08-03T10:30:00+03:00"},
    {"event": "applied", "ts": "2026-08-03T11:00:00+03:00"}
  ]
}
```

### Правило: данные не удаляются

Вакансии в `store.json` никогда не удаляются автоматически. Если вакансия пропала с hh — у неё обновляется поле `accessible: false`. История остаётся.

Это важно: по накопленным данным Claude может давать карьерные советы — где были отказы, какие типы вакансий приводят к интервью.

### Пересборка отчёта без сбора

Если хочешь пересобрать отчёт без похода на hh (например, после изменения `config.json`):

```bash
python src/rescore.py    # пересчитать баллы по новым правилам
python src/build_report.py  # собрать отчёт
```

Или через кнопку «Пересобрать» в отчёте.

## 10. Продвинутая настройка скоринга

### Как работает v2-скоринг

1. Определяется **тип вакансии** — задаётся в `config.json` и `.claude/CAREER_ASSISTANT_V2.md`
2. Считается **Score**: базовые 50 + бонусы за технологии − штрафы
3. Применяется **базовая вероятность** по типу вакансии
4. Применяются **дополнительные коэффициенты** (Senior, English, расписание)
5. Итог: `финальный_ранг = score × вероятность`

### Типы вакансий и базовые вероятности

Типы и вероятности настраиваются под твой стек в `config.json` (`v2.type_prob`). Пример структуры:

| Тип | Базовая вероятность | Когда применяется |
|-----|--------------------|--------------------|
| `[type_primary]` | 95–98% | Основная специализация кандидата |
| `[type_secondary]` | 85–92% | Близкий стек, есть опыт |
| `[type_learning]` | 62–75% | Стек в изучении, есть базовый опыт |
| `[type_adjacent]` | 55–70% | Смежное, частичное совпадение |
| `[unwanted_type]` | 0% | Автоматический отказ |

### Коэффициенты-модификаторы

| Условие | Коэффициент |
|---------|------------|
| Senior (жёсткие требования) | ×0.50 |
| Senior (мягкие требования) | ×0.85 |
| Обязательный английский | ×0.85 |
| Нестандартный график | ×0.50 |

### Пересчёт после изменения правил

После изменения `config.json` запусти:

```bash
python src/rescore.py
```

Это пересчитает баллы для ВСЕХ вакансий в `store.json` по новым правилам без парсинга hh.

## 11. Решение проблем

### Отчёт пустой при первом запуске

Нормально — `store.json` ещё пустой. Запусти сбор вакансий:

```bash
python src/collect.py
python src/build_report.py
```

### Кириллица в логах выглядит как `??????`

Запускай скрипты с явным указанием кодировки:

```bash
# Windows CMD
set PYTHONIOENCODING=utf-8
python src/collect.py

# PowerShell
$env:PYTHONIOENCODING="utf-8"

```

`start.bat` делает это автоматически.

### Порт 8765 уже занят

В `src/serve.py` найди строку `PORT = 8765` и замени на другой номер (например, `8766`).

### Вакансия показывает 403 при загрузке деталей

hh.ru иногда блокирует парсинг. Сбор продолжится — вакансия добавится с минимальными данными из поиска (без описания и навыков). При следующем обновлении попробует снова.

### Как сбросить все статусы и начать заново

Удали `data/store.json` и запусти `collect.py`. **Внимание:** потеряются все письма, статусы и история.

Лучше не удалять — вместо этого поставь статус `archived` нежелательным вакансиям через Claude.

### Как добавить новые поисковые запросы без потери данных

Просто добавь запрос в `config.json` в массив `queries` и запусти обновление. Старые вакансии сохранятся, новые добавятся.
